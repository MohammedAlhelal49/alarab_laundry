# تقرير تحليل موديول Dekad Auto Database Backup

**التاريخ:** 31 يناير 2025  
**الإصدار المُحلّل:** 18.0.1.0.0

---

## 1. نظرة عامة على الموديول

الموديول يوفر نسخ احتياطي تلقائي لقاعدة بيانات Odoo مع:
- جدولة مرنة (نافذة زمنية + عدد النسخ يومياً)
- تنظيف تلقائي للملفات القديمة
- سجل تفصيلي لكل عملية
- دعم نسخ يدوي وفوري

---

## 2. هيكل المنطق

### 2.1 تدفق النسخ المجدول (Cron كل 10 دقائق)

```
run_scheduled_backups()
    │
    ├─► ترحيل تلقائي (إن وجدت إعدادات قديمة على الشركات)
    │
    ├─► إذا التعطيل: خروج
    │
    ├─► حساب الفتحات الزمنية اليومية (_compute_today_slots)
    │
    ├─► due_slots = فتحات أصبح وقتها قد حان (slot <= now)
    │
    ├─► target_slot = أحدث فتحة مستحقة
    │
    ├─► إذا last_backup >= target_slot: خروج (تم تنفيذ هذه الفتحة)
    │
    └─► تنفيذ النسخ + تحديث dekad_last_backup_at
```

### 2.2 حساب الفتحات الزمنية (_compute_today_slots)

- **per_day = 1:** فتحة واحدة عند وقت البداية
- **per_day > 1:** توزيع متساوٍ بين وقت البداية ووقت النهاية

**مثال:** 08:00–18:00 مع 3 نسخ/يوم → 08:00, 13:00, 18:00

### 2.3 السيناريوهات المُغطاة

| السيناريو | السلوك |
|-----------|--------|
| نسخ يدوي | لا يؤثر على المجدول ولا على `dekad_last_backup_at` |
| نسخ مجدول | يعتمد على الفتحات + `dekad_last_backup_at` لتجنب التكرار |
| بداية يوم جديد | `last_tz` (أمس) < `target_slot` (اليوم) → يتم النسخ |
| تعطيل النسخ | لا يُنفذ النسخ المجدول |
| `dekad_backup_daily = False` | بعد أول نسخ يتم التعطيل |

## 3. الأخطاء المكتشفة

### 3.1 خطأ حرج: `res_company.py` – استخدام خاطئ لـ timedelta

**الموقع:** `models/res_company.py` السطر 94

**الكود الحالي:**
```python
limit_date = fields.Datetime.now() - fields.timedelta(days=170)
```

**المشاكل:**
1. `fields.timedelta` هو نوع حقل (Field type)، وليس دالة لإنشاء فاصل زمني.
2. `fields.Datetime.now()` يُرجع نصاً (string)، والطرح منه يفشل.

**التصحيح المقترح:**
```python
from datetime import timedelta

# ...
limit_date = fields.Datetime.subtract(fields.Datetime.now(), days=170)
# أو:
# now_dt = fields.Datetime.from_string(fields.Datetime.now())
# limit_date = fields.Datetime.to_string(now_dt - timedelta(days=170))
```

---

### 3.2 خطأ حرج: `res_company.py` – استيراد مفقود لـ `os`

**الموقع:** `models/res_company.py` السطر 109

**الكود الحالي:**
```python
backup_dir = os.path.join(backup_root, self.env.cr.dbname)
```

**المشكلة:** لم يتم استيراد `os`، مما يسبب `NameError` عند تشغيل `clean_database_backup`.

**التصحيح:** إضافة `import os` في بداية الملف.

---

### 3.3 تحذير: عدم تعريف تسلسل للأسماء في السجل

**الموقع:** `models/backup_log.py` السطر 33

**الكود:**
```python
vals["name"] = self.env["ir.sequence"].next_by_code("dekad.backup.log") or "New"
```

**المشكلة:** لا يوجد سجل `ir.sequence` بكود `dekad.backup.log` في ملفات البيانات، مما يؤدي لاستخدام "New" لكل السجلات.

**التصحيح:** إضافة ملف بيانات XML لتعريف التسلسل، أو تعريف التسلسل من الموديول.

---

### 3.4 تحذير: مسار النسخ الاحتياطي الافتراضي

**الموقع:** `backup_config.py` السطور 141–142

**الكود:**
```python
base_data_dir = config["data_dir"]
backup_root = base_data_dir.replace("storage", "backups")
```

**المشكلة:** الاعتماد على وجود "storage" داخل `data_dir`. إذا كان المسار مختلفاً (مثلاً `/var/lib/odoo`)، لن يحدث استبدال صحيح.

**التوصية:** استخدام مسار صريح مثل `os.path.join(base_data_dir, "backups", dbname)` بدلاً من `replace`.

---

### 3.5 تحذير: تشغيل نسخ متزامن (بدون قفل)

**المشكلة:** الكرون يعمل كل 10 دقائق، والنسخ قد يستغرق عدة دقائق. احتمال تشغيل نسختين في نفس الوقت.

**التوصية:** إضافة آلية قفل (مثلاً حقل `dekad_backup_in_progress` أو استخدام `flock`) لمنع النسخ المتزامن.

## 4. توافق تعدد السيناريوهات

### 4.1 قاعدة بيانات واحدة، عدة شركات

- يوجد إعداد مركزي واحد (`dekad.backup.config`).
- الكرون يستدعي `res.company.run_scheduled_backups()` مرة واحدة لكل قاعدة بيانات.
- لا تعارض بين الشركات.

### 4.2 عدة قواعد بيانات (Odoo متعدد)

- كل قاعدة لها نسخة مستقلة من الموديول والإعدادات.
- الكرون يعمل لكل قاعدة على حدة.
- لا تعارض بين قواعد البيانات.

### 4.3 النسخ اليدوي والمجدول

- النسخ اليدوي: لا يحدّث `dekad_last_backup_at`.
- النسخ المجدول يستخدم فقط `dekad_last_backup_at` لتحديد ما إذا تم تنفيذ الفتحة الحالية.
- لا تعارض منطقي.

### 4.4 الترحيل من إعدادات قديمة (Legacy)

- يتم فقط عند:
  - `dekad_backup_enabled = False` في الإعداد المركزي، و
  - `dekad_last_backup_at` فارغ.
- يتم تعطيل النسخ على جميع الشركات بعد الترحيل.
- احتمال تشغيل الترحيل مرتين متزامناً منخفض جداً بسبب تكرار الكرون.
